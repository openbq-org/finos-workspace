# Give the Agent tools from an MCP server

An MCP server gives the Agent more tools: it can search a knowledge base, query a system of your company or call any service that someone has wrapped in the Model Context Protocol. This guide connects such a server to your account, signs you in to it when it needs that, and checks that the Agent can use it.

## What you need

You need an account of type Admin or Developer, because a User cannot add servers, and the address of the server's MCP endpoint. FINOS Workspace supports servers that speak streamable HTTP only, and it does not support servers that run as a local process over stdio or that use the older SSE transport.

The Agent can use every tool of a server that you add yourself, because adding the server is the approval, as connecting a backend of your own is. A server does not have to belong to a backend. Every user already has the servers that the deployment adds for everyone, such as Agent Tools, and a backend can bring servers along in two ways: the `mcpServers` of its apps, which FINOS Workspace adds when you connect the backend, and the `storage.mcpUrl` of an `iframe` widget, which FINOS Workspace connects for the widget, as [Link a widget to an MCP tool](../../tutorials/build-a-backend/link-a-widget-to-an-mcp-tool.md) describes. Whoever can use the backend can use every tool of those servers. The tools of any other server work for you only when one of your roles grants them, as [Choose the models and tools of a role](../administration/choose-the-models-and-tools-of-a-role.md) describes.

## Add the server

1. Select AI in the sidebar, and then the tab MCP Servers.
2. Select Add Server. The dialog Add MCP Server opens.
3. In Name, type the name that the list shows.
4. In URL, type the address of the server's MCP endpoint.
5. Leave Client Name empty, unless the server expects another name. It is the name that FINOS Workspace gives the server when it connects, and it is `FINOS Workspace` when you leave it empty.
6. When the server needs a header, such as `Authorization: Bearer <token>`, select Add Custom Header and fill in the name and the value of each header.
7. Select Add.

FINOS Workspace connects to the server at once, and the row shows Connecting… until it is done. A message says "Connected to" and the server's name, the row shows a green dot, and the number in brackets is the number of tools that the server offers. When the connection fails, the message says "Failed to connect to" and the server's name. Open the server's row to read its tools and their descriptions.

## How FINOS Workspace reaches the server

The FINOS Workspace API makes every call to the server, as it does for a data backend. Your browser sends each request to the API, which adds the headers that you saved and forwards it. The browser never connects to the server and never holds a header, so the server needs no CORS settings and sees the address of the API. Which addresses the API reaches depends on who keeps the connection:

- **A public `https` address** works for everyone.
- **A private address or a plain `http` address** works for a superuser, and for every user on a local stack, where the API runs with `MODE=local`. For anyone else, a host name that resolves to a private, loopback or link-local address does not work, and neither does an address given as a number. An admin lists such hosts for everyone in the setting `ALLOWED_MCP_HOSTNAMES`, as [Backend settings](../../reference/configuration/backend.mdx) describes.
- **A server on your own computer** works on a local stack. Give the address that you use in your browser, for example `http://localhost:8787/mcp`, and the API reaches your computer through `host.docker.internal`. On Linux the server has to listen on `0.0.0.0`. A deployed FINOS Workspace cannot reach a server on your computer, because its API makes the calls from the deployment's network.

## Sign in to the server

Servers differ in how they know who you are:

- **A server with its own sign-in (OAuth).** When the server answers that you have to sign in, FINOS Workspace opens a window with the server's sign-in page, and the window closes by itself when you have finished. FINOS Workspace waits for <WebAppValue of="mcpAuthTimeoutMs" unit="ms" />. When you take longer, the connection fails with "Authentication timed out. Please try again.", and you connect again.
- **A server with a token.** Give the token as a custom header when you add the server. When the server refuses it, the message says "Couldn't authenticate with" and the server's name, and asks you to check that the token is valid and has not expired.

## Use the server

Open the Agent and select the control with a number next to the gear, which lists your MCP servers and their tools as [Ask the Agent about a dashboard](ask-the-agent-about-a-dashboard.md#change-the-agents-settings) describes. A tick next to a server or a tool lets the Agent use it for your questions. When you ask a question, the Agent decides by itself whether a tool helps, calls it through your browser, and shows the call among its steps.

## Disconnect, edit or delete the server

The row of a server has a button Disconnect, which ends the connection and keeps the server in the list, and a button Connect that starts it again. The pencil edits the server in the dialog Edit MCP Server, and the trash can deletes it, after which a message says that the server was deleted successfully.
